fixdossier / Privacy

Privacy notice

Last updated: 22 November 2026. This notice covers the website fixdossier.dev, the free fixdossier GitHub Action (itulo/fixdossier) and the hosted service fixdossier Pro at app.fixdossier.dev. It describes what the software actually does today.

Who is responsible

The controller is Italo Armenti, a private individual in Finland. Contact: contact@fixdossier.dev. There is no data protection officer.

Short version

  • The website sets no cookies. Page views are counted as anonymous daily totals.
  • The GitHub Action sends nothing to us unless you turn on pro_upload or set pro_token.
  • fixdossier Pro stores what it needs to run your account and licence: your GitHub identity, your organization, the security records your CI uploads, your review decisions, and the payment record that Dodo Payments sends us.
  • Nothing in the Pro database is deleted automatically. Data stays until you ask us to delete it, or until the service shuts down (with at least 90 days' notice and an export).

1. The website (fixdossier.dev)

  • Hosting. The site is static and hosted by GitHub Pages. GitHub receives your IP address and browser details when it serves the pages, under GitHub's own privacy statement.
  • Fonts. The fonts are served from this site itself. No third-party font service is contacted.
  • Theme setting. If you switch between light and dark mode, that choice is saved in your browser's local storage (fixdossier_theme). It never leaves your browser.
  • Page-view counter. Each page sends one request to app.fixdossier.dev/b with only a page name (for example home). The server adds 1 to that page's total for the day (UTC). The counter stores no IP address, browser details, cookie or other identifier, and nothing is sent when your browser has Do Not Track or Global Privacy Control turned on. The request passes through Cloudflare and our server, which does not write it to the web server log (see sections 4 and 5).
  • No cookies, no advertising and no third-party analytics on fixdossier.dev.

2. The GitHub Action

The Action runs inside your own GitHub Actions workflow. It reads your repository's releases, tags, published security advisories, closed pull requests and commit list through the GitHub API, using the token you give it (by default GITHUB_TOKEN). It writes SECURITY-RECORD.md, security-record.json and SUPPORT.md into your workflow. By default (pro_upload: false, no pro_token) it sends nothing to us.

If you set pro_upload: 'true' or a pro_token, the Action sends one request to https://app.fixdossier.dev/api/v1/ingest (or your pro_url) containing:

  • the generated security-record.json: release names, tags, dates and URLs; advisory IDs, titles and severities; Dependabot/Renovate pull-request titles; and, for commits that look like security fixes, the commit SHA, URL and the first line of the commit message (up to 160 characters). It contains no source files and no commit author names;
  • request headers with the repository name, repository owner, owner ID, workflow run ID, commit SHA, git ref and workflow name, and, if something went wrong on your side, a short error message;
  • a short-lived GitHub Actions OIDC token, or your fxd_tok_… upload token. The OIDC token is signed by GitHub and also contains claims about the run (for example the repository, ref, workflow and the GitHub account that triggered it). We verify it and read the repository, owner, run, SHA, ref and workflow claims. We do not store the token.

4. Logs and backups

  • Application logs. The app writes only start-up, shutdown and error messages. It does not log individual requests. These logs are rotated daily (or at 10 MB), and only the 10 most recent rotated files are kept; older files are deleted.
  • Web server logs. nginx on our server writes standard access logs for app.fixdossier.dev: time, the connecting IP address (yours, or a Cloudflare address), the requested URL including any query string, status, size, referrer and browser details. They are rotated daily and deleted after 14 days. Health checks and requests to the page-view counter are not logged.
  • Backups. There are no automatic backups.

5. Who processes data for us

  • Dodo Payments is the merchant of record. It sells you the licence, takes the payment, handles tax and invoices, and processes your payment data under its own privacy policy.
  • Hetzner Online GmbH hosts the fixdossier Pro server and database in its Helsinki data centre in Finland.
  • GitHub provides sign-in (OAuth), the OIDC tokens used for uploads, the Action's runtime, and hosting for this website (GitHub Pages).
  • Cloudflare provides DNS for fixdossier.dev, proxies traffic to app.fixdossier.dev, and routes email sent to contact@fixdossier.dev to the controller's mailbox.
  • Google hosts the Gmail mailbox that contact@fixdossier.dev forwards to.

Some of these companies may process data outside the EU/EEA under their own terms and transfer safeguards.

6. Your rights

You can ask for a copy of your data, correction, deletion, restriction, or to object to processing based on legitimate interest. You can also export your organization's whole workspace yourself at any time from /app/export.zip. Deletion is done by hand on request. Email contact@fixdossier.dev from the address linked to your account, or tell us your GitHub login. We answer within one month.

You can complain to the Finnish supervisory authority, the Data Protection Ombudsman (Tietosuojavaltuutetun toimisto), at tietosuoja.fi/en, or to the authority in your own EU country.

7. Changes

We will update this page when the software changes how it handles data, and change the date at the top.
